[P-Heading 1] 1  引言
[P-Heading 2] 1.1  编写目的
[P-Normal] 本需求规格说明书旨在对“在线小说书城系统”的项目背景、系统目标、功能需求、非功能需求、数据需求、接口需求及总体架构进行完整、明确的定义，为后续的系统设计、编码实现、测试验收以及毕业设计论文撰写提供统一的基线依据。本文档面向的读者包括：毕业设计指导教师、系统设计开发人员、测试人员以及答辩评审人员。
[P-Heading 2] 1.2  项目背景
[P-Normal] 随着互联网与移动阅读的普及，网络文学平台已成为数字内容消费的重要形态。以番茄小说为代表的一批平台将“免费阅读 + 付费章节 + 作者分成”的商业模式跑通，其核心业务可抽象为“内容生产（作者创作）—内容分发（平台展示与推荐）—内容消费（读者阅读与付费）”的完整闭环。
[P-Normal] 本毕业设计以番茄小说的基础能力为参照，设计并实现一个 B2C 在线小说书城系统：面向读者提供小说浏览、分类检索、试读、付费购买与在线阅读能力；面向作者提供入驻申请、作品创建与章节发布能力；面向管理员提供作者审核、内容审核与运营管理能力，从而覆盖网络文学平台的基础业务链路，达到本科计算机科学与技术专业毕业设计的规模与深度要求。
[P-Heading 2] 1.3  术语定义
--- TABLE 1 ---
术语 | 定义
读者 | 注册并使用系统阅读小说的普通用户。
作者 | 通过入驻审核后，在平台创建并发布小说作品的用户。
管理员 | 负责系统运营管理、内容审核与秩序维护的后台管理人员。
试读 | 对付费内容开放的前置免费章节或片段，用于引导读者购买。
付费章节 | 需要读者购买后（余额扣减并生成有效订单）方可阅读的章节。
书架 | 读者收藏或正在阅读小说的聚合入口，可展示阅读进度。
模拟支付 | 不接入微信/支付宝等真实支付渠道，通过模拟充值余额与模拟回调完成订单状态流转。
入驻审核 | 作者提交入驻申请后，由管理员对其资质进行审核的过程。
RAG | 检索增强生成（Retrieval-Augmented Generation），本项目简化为基于文本向量相似度的小说片段检索。
--- END TABLE 1 ---

[P-Heading 1] 2  项目概述
[P-Heading 2] 2.1  项目目标
[P-Normal] （1）完成一个功能完整、可运行演示的 B2C 在线小说书城系统，实现读者端、作者端、管理员端三大角色的核心业务闭环；
[P-Normal] （2）采用 SpringBoot + MyBatis-Plus + MySQL + Vue3 + Element Plus 主流技术栈，满足本科毕设技术要求，并可作为求职简历中的完整项目经历；
[P-Normal] （3）集成 RocketMQ 消息中间件完成“下单异步处理、站内通知、销量统计、订单超时自动关闭”等进阶能力，作为答辩亮点；可选实现简单 RAG 小说片段检索作为加分项；
[P-Normal] （4）形成需求、设计、实现、测试等完整过程文档与可演示系统，支撑论文撰写与毕业答辩。
[P-Heading 2] 2.2  系统定位与建设原则
[P-Normal] 系统定位为 B2C 小说书城平台，对标番茄小说基础能力，采用“读者端 + 作者入驻后台 + 管理员后台”的三端架构。为保证毕业设计按期高质量完成，明确以下建设原则：
[P-Normal] 范围聚焦原则：聚焦“看书、购书、作者入驻”三大核心业务，不扩展直播、广告、会员订阅等非核心功能；
[P-Normal] 支付简化原则：不接入真实微信/支付宝支付，采用模拟充值 + 模拟支付回调，仅实现订单状态流转逻辑；
[P-Normal] 内容存储原则：小说章节正文以数据库文本字段存储，单章节体积可控，不做超大文件上传与对象存储；
[P-Normal] 版权合规原则：测试小说文本由项目组自行撰写，不使用受版权保护的正版小说内容；
[P-Normal] 技术主流原则：前后端分离，核心功能优先跑通，技术栈兼顾毕设评分与简历含金量。

[P-Heading 2] 2.5  设计约束与假设
[P-Normal] （1）支付为模拟实现：系统内置余额账户，模拟充值成功后直接扣减余额完成支付，不调用第三方支付接口；
[P-Normal] （2）章节正文以数据库文本字段（TEXT/MEDIUMTEXT）存储，不涉及大文件上传、分片存储与对象存储；
[P-Normal] （3）系统规模面向毕业设计演示场景，不要求承载大规模高并发，但需保证常规操作响应流畅；
[P-Normal] （4）身份证号等敏感信息仅做简化实名认证登记，展示时脱敏处理；
[P-Normal] （5）所有测试数据（含小说标题、简介、正文）均由项目组自写，仅用于系统演示与测试。

[P-Heading 2] 3.2  读者端功能需求
[P-Heading 3] 3.2.1  用户注册与登录
[P-Normal] 读者通过用户名 + 密码完成注册与登录。注册时校验用户名唯一性、密码强度与格式；密码采用加密算法存储，禁止明文入库。登录成功后签发访问令牌（Token），前端携带令牌访问受保护接口；支持退出登录与令牌失效。个人中心支持查看与修改昵称、头像、密码等基础信息。
[P-Heading 3] 3.2.2  首页与小说浏览
[P-Normal] 首页提供小说推荐位（如编辑推荐、最新上架）、分类入口（玄幻、都市、言情、悬疑、科幻、历史等）与排行榜（按人气、收藏、更新等维度）。分类浏览支持按分类筛选小说，列表展示封面、书名、作者、简介摘要与连载状态。
[P-Heading 3] 3.2.3  小说搜索
[P-Normal] 支持按“小说名称”“作者名称”进行关键词模糊搜索，结果列表展示匹配的小说；搜索支持空态提示与结果分页。
[P-Heading 3] 3.2.4  小说详情与试读
[P-Normal] 小说详情页展示封面、书名、作者、分类、简介、最新章节信息与完整章节列表。免费章节可直接试读；付费章节在未购买时提示价格与购买入口，已购买后可正常阅读。详情页同时提供收藏、评论入口。
[P-Heading 3] 3.2.5  在线阅读与阅读进度
[P-Normal] 阅读页展示章节正文，支持上一章/下一章切换。系统自动记录读者对每本小说的阅读进度（当前章节、章节内位置），读者再次进入时提示“继续阅读”；阅读记录在书架与个人中心中可查看。
[P-Heading 3] 3.2.6  书架与收藏
[P-Normal] 读者可将小说加入书架并收藏。书架聚合展示“正在阅读”与“已收藏”的小说，显示阅读进度与更新时间，支持从书架快速进入阅读页。
[P-Heading 3] 3.2.7  评论
[P-Normal] 读者可对小说发表评论，评论内容需通过基础敏感词过滤与长度校验；评论列表按时间倒序展示；管理员可对违规评论进行下架或删除。
[P-Heading 3] 3.2.8  模拟充值、付费购买与订单
[P-Normal] 系统内置读者余额账户，支持模拟充值（充入固定金额即增加余额）。付费购买支持“购买单章”与“购买整本”两种模式：下单时校验余额是否充足，余额充足则扣减余额、生成已支付订单，并放行付费章节阅读权限；余额不足则提示充值。购买成功后通过 RocketMQ 异步发送消息，完成站内通知、销量统计等后续处理（详见 3.5.1）；未支付订单在超时后由死信队列自动关闭（详见 3.5.2）。
[P-Heading 3] 3.2.9  个人中心
[P-Normal] 个人中心集中展示：基础信息、我的书架、购买记录（订单列表）、阅读记录、评论记录、充值记录与余额。
[P-Heading 2] 3.3  作者端功能需求
[P-Heading 3] 3.3.1  作者入驻
[P-Normal] 读者可提交作者入驻申请：填写真实姓名、身份证号（简化实名认证，脱敏展示）与作者简介。申请提交后进入“待审核”状态；管理员审核通过后该账号升级为作者角色，可创建作品；驳回时返回原因，支持修改后重新提交。
[P-Heading 3] 3.3.2  作品管理
[P-Normal] 作者可创建新小说：上传封面、填写书名、简介并选择分类（分类从管理员维护的分类字典中选择）。支持编辑作品信息、查看作品状态（连载中/已完结/已下架），并管理作品下全部章节。
[P-Heading 3] 3.3.3  章节管理
[P-Normal] 作者可对作品进行章节的新增、编辑、删除，章节内容以文本形式提交。每个章节可设置免费或付费属性；付费章节需设置价格；章节按创建顺序（或手动排序号）排列。发布后章节进入审核或直接可见流程（由管理员审核策略决定，见 3.4.3）。
[P-Heading 3] 3.3.4  数据看板与收益统计
[P-Normal] 作者可查看本人作品的阅读量、付费阅读次数与收益统计（按作品维度聚合）。收益 = 付费章节收入合计（模拟口径），数据看板以列表与图表方式呈现，支持按时间范围筛选。
[P-Heading 2] 3.4  管理员端功能需求
[P-Heading 3] 3.4.1  用户管理
[P-Normal] 管理员可查看全部用户列表，支持按用户名/角色检索，可对用户进行禁用/启用操作（禁用后无法登录）。
[P-Heading 3] 3.4.2  作者入驻审核
[P-Normal] 管理员可查看作者入驻申请列表（含申请人信息与申请材料），执行“通过”或“驳回”操作，驳回需填写原因；审核结果实时反馈给申请人。
[P-Heading 3] 3.4.3  小说内容审核
[P-Normal] 管理员可查看全部小说及其状态，对小说执行上架/下架操作；下架后读者端不可见。同时可对章节内容进行抽查审核（简化策略：默认作者发布的章节直接上架，管理员可随时下架违规内容）。
[P-Heading 3] 3.4.4  分类管理
[P-Normal] 管理员可对小说分类进行新增、编辑、删除与排序，分类变更实时影响读者端分类浏览。
[P-Heading 3] 3.4.5  订单管理
[P-Normal] 管理员可查看全部订单列表，按订单号、用户名、支付状态、订单类型检索；可查看超时自动关闭订单的处理结果与异常订单。
[P-Heading 3] 3.4.6  评论管理
[P-Normal] 管理员可查看全部评论，对违规评论执行删除/屏蔽操作；支持按小说或用户名筛选。
[P-Heading 2] 3.5  加分模块需求
[P-Heading 3] 3.5.1  RocketMQ 异步消息处理
[P-Normal] 读者下单（购买章节/整本）成功后，系统通过 RocketMQ 异步发送业务消息，消息消费端分别完成：①订单落库与状态确认；②站内通知生成（如“购买成功”提醒）；③销量统计更新（作品付费次数、平台订单数）。异步化将耗时操作移出主链路，提升下单接口响应速度，同时体现消息队列解耦与削峰的设计思想。
[P-Heading 3] 3.5.2  订单超时自动关闭（延迟消息 + 死信队列）
[P-Normal] 订单创建时发送延迟消息（如 15 分钟），延迟到期后消息进入死信队列，由专门消费端消费并检查订单支付状态：若仍未支付则自动将订单置为“已关闭”，释放占用的余额或额度。该机制模拟真实电商“下单未支付自动关单”场景，是面试中可重点阐述的 RocketMQ 应用案例。
[P-Heading 3] 3.5.3  简单 RAG 小说片段检索（可选）
[P-Normal] 对小说章节内容进行分块与向量化，建立片段向量索引；读者输入一句话（自然语言查询）时，将其向量化后在索引中检索语义最相近的小说片段并返回原文与出处（书名、章节）。该模块用于展示检索增强思路，作为项目加分项，可视开发进度决定是否实现。

[P-Heading 1] 4  非功能需求
[P-Heading 2] 4.1  性能需求
[P-Normal] （1）常规并发（演示规模）下，核心接口响应时间不超过 500ms；
[P-Normal] （2）小说列表、搜索、详情等高频查询接口支持分页，单页数据量不超过 20 条；
[P-Normal] （3）章节正文读取接口具备缓存优化空间（可后续引入 Redis），保证长文阅读流畅；
[P-Normal] （4）系统可支撑 100 个以上并发用户同时在线的基本操作。
[P-Heading 2] 4.2  安全需求
[P-Normal] （1）用户密码采用 BCrypt 等加盐哈希算法加密存储，任何接口不得返回明文密码；
[P-Normal] （2）登录鉴权采用 Sa-Token 令牌机制，受保护接口必须校验登录态与角色权限；
[P-Normal] （3）后端统一进行参数校验，防止 SQL 注入、XSS 等常见 Web 攻击；
[P-Normal] （4）管理员、作者、读者三端接口按角色隔离，越权访问一律拒绝；
[P-Normal] （5）身份证等敏感信息脱敏展示，日志中不得记录完整敏感字段。
[P-Heading 2] 4.3  可用性与易用性
[P-Normal] 界面采用 Vue3 + Element Plus 组件库，风格统一、交互清晰；关键操作（下单、审核、发布）有明确的结果反馈；系统提供统一的错误提示与空数据状态；支持 Chrome / Edge 等主流浏览器。
[P-Heading 2] 4.4  可维护性与可扩展性
[P-Normal] 后端采用分层架构（Controller / Service / Mapper），前端按页面组件化开发；提供统一返回体、统一异常处理与日志记录；数据库表结构清晰、外键关系明确，便于后续功能扩展（如接入真实支付、引入 Redis 缓存、扩展推荐算法等）。
[P-Heading 2] 4.5  版权与内容合规
[P-Normal] 系统内所有小说测试数据均为项目组自写内容，不引用受版权保护的正版小说文本；平台提供基础的内容审核与下架机制，管理员可对违规作品、章节与评论进行处理，保障内容合规性。

[P-Heading 1] 6  接口需求
[P-Heading 2] 6.1  用户界面需求
[P-Normal] 前端采用 Vue3 + Element Plus 组件库构建，按读者端、作者端、管理员端划分三套页面布局：读者端面向小说阅读场景（首页、分类、详情、阅读页等），作者端面向创作管理场景（作品、章节、数据看板），管理员端面向运营管理场景（列表与审核操作）。界面风格统一、操作反馈明确，基础适配桌面端主流分辨率。
[P-Heading 2] 6.2  软件接口需求
[P-Normal] 后端对外提供 RESTful 风格 API，统一请求/响应规范：响应体格式为 {code, message, data}，分页参数统一为 page/pageSize，认证采用 Sa-Token 签发 Token，前端通过请求头携带。接口按业务模块分组（用户、小说、章节、书架、订单、评论、审核、统计等），关键接口设计将在系统设计阶段细化。
[P-Heading 2] 6.3  硬件接口需求
[P-Normal] 系统无特殊硬件接口需求，部署于常规 PC 服务器或本地开发机即可运行。
[P-Heading 1] 7  系统总体架构设计
[P-Heading 2] 7.1  技术架构
[P-Normal] 系统采用前后端分离的分层架构：前端基于 Vue3 + Element Plus + Axios 构建三端页面，通过 HTTP 请求与后端交互；后端基于 SpringBoot 搭建，采用 Controller / Service / Mapper 三层结构，MyBatis-Plus 负责数据库访问，Sa-Token 负责登录鉴权与角色权限控制；数据层采用 MySQL 8.0 存储业务数据；可选集成 RocketMQ 消息中间件处理下单异步任务与订单超时关单，可选集成简单 RAG 实现小说片段检索。整体架构如图 7-1 所示。

[P-Heading 2] 7.2  关键业务流程
[P-Heading 3] 7.2.1  付费购买流程（含 RocketMQ 异步）
[P-Normal] ①读者在小说详情页选择“购买单章/整本”发起下单；②系统校验登录态、章节付费属性与余额，创建订单并进入“待支付”状态，同时发送 RocketMQ 延迟消息（如 15 分钟后超时检查）；③读者确认支付，系统扣减余额并将订单置为“已支付”，放行付费章节阅读权限；④订单支付成功消息异步通知消费端，完成站内通知生成与销量统计更新；⑤若读者未在延迟时间内支付，延迟消息到期进入死信队列，消费端检查订单仍为“待支付”则自动关闭订单。
[P-Heading 3] 7.2.2  作者入驻审核流程
[P-Normal] ①读者提交入驻申请（真实姓名、身份证号、简介），作者记录进入“待审核”状态；②管理员在后台查看申请列表并执行审核；③审核通过则该账号获得作者角色并进入作者端；审核驳回则返回原因，申请人可修改后重新提交。
[P-Heading 3] 7.2.3  小说发布与审核流程
[P-Normal] ①作者在作者端创建小说（封面、书名、简介、分类）并分章节上传正文；②章节提交后默认进入“已发布”状态，读者端可见（简化策略：不做逐章强制审核，采用“先发后审”）；③管理员对小说执行上架/下架操作，下架后读者端不可见，实现内容管控。
